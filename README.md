# DXF 自动拆图：从事实审计开始

这是一个从零重做的 DXF 自动拆图项目。

旧版本的问题不是功能不够，而是不断为个别图纸增加补偿规则，最终导致坐标、归属、块变换和输出逻辑相互耦合。新版本采用“先建立事实，再做判断”的路线：任何自动拆图规则都必须建立在可检查的坐标和实体事实之上。

## 当前阶段

当前已经实现：运行程序后选择 DXF 文件、识别图框并生成保守分割结果。

直接运行程序时，程序会自动打开项目内的 `原始文件/` 目录。选择并确认文件后，当前版本分析模型空间中的 `INSERT` 块族：优先寻找同一块定义内部的外细内粗完整边框对；DXF 未记录明确线宽时，多层嵌套只作为辅助证据。同一块定义允许按不同比例插入，尺寸不再作为正式边框族的硬门槛。对于只出现一次、但外框比例和内外矩形结构与已确认图幅相近的块，补充为单次同形图幅候选，不使用块名、文字或图层语义判断。随后按实体变换后包围盒执行保守分割，跨边界、无法定位和图框外实体进入共享内容文件。原始 DXF 不会被修改。

当前保留的 `audit` 命令是开发阶段的事实审计工具。它只读取文件，不修改源文件，不识别图框，不执行实体归属，也不导出拆分图纸。它首先回答：

- 文件包含哪些 Layout 和 Model Space；
- 模型空间实体有哪些类型和图层；
- 每个实体是否能计算出可靠的有限包围盒；
- 文件中有哪些 `INSERT`，它们的插入点、旋转、缩放和阵列参数是什么；
- 模型空间的整体坐标范围是多少；
- 哪些实体无法定位，原因是什么。

## 安装

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

项目输入范围固定为 DXF，不处理 DWG，也不包含 DWG 转换层。这样可以把问题集中在 DXF 的坐标空间、块变换、实体边界和图纸归属上。

## 使用

在项目根目录运行：

```powershell
python main.py
```

程序会打开文件选择窗口，默认进入 `原始文件/`，只显示 `.dxf` 文件。选择后生成：

```text
输出文件/<源文件名>/识别报告.md
输出文件/<源文件名>/识别调试报告.md
输出文件/<源文件名>/识别数据.json
输出文件/<源文件名>/图框_*.dxf
输出文件/<源文件名>/共享内容.dxf
输出文件/<源文件名>/拆分报告.md
输出文件/<源文件名>/拆分数据.json
```

其中 `识别报告.md` 只展示正式图框候选；`识别调试报告.md` 才包含内部矩形和 INSERT 块族明细；`拆分报告.md` 记录归属统计和输出文件；JSON 保留完整识别数据。

取消选择时安全退出。

开发阶段如需执行事实审计，可以运行：

```powershell
python main.py audit "原始文件\7号楼立面图.dxf"
```

默认在输入文件同目录生成：

```text
原始文件\7号楼立面图_audit.json
```

也可以指定输出路径：

```powershell
python main.py audit "原始文件\7号楼立面图.dxf" -o "审计结果\7号楼立面图.json"
```

如果需要把每个模型空间实体的包围盒都写入报告：

```powershell
python main.py audit "原始文件\7号楼立面图.dxf" --include-entities
```

大型文件使用 `--include-entities` 后报告会明显变大，默认只输出统计、块变换和无法计算边界的实体。

## 新版算法原则

1. 坐标事实优先于图框启发式；
2. 模型空间和布局空间明确分开；
3. 块局部坐标、插入变换和最终模型坐标明确分层；
4. 快速估计不能直接作为最终归属依据；
5. 不确定归属必须显式标记，不能通过补偿规则强行分配；
6. “实体没有丢失”和“实体归属正确”分别验证；
7. 每个阶段都有独立的输入、输出和可检查报告；
8. 复杂对象优先保真，不能为了裁剪而破坏源文件结构。

## 后续开发顺序

### 1. 坐标审计

完善 WCS、UCS、OCS、Layout、Viewport、单位和块嵌套变换的记录，建立统一的模型坐标表示。

### 2. 图框候选审计

只生成候选，不立即接受。每个候选记录来源、坐标、变换、几何质量和风险，不在本阶段导出图纸。

### 3. 可视化核对

将候选图框和实体边界生成可检查的标注结果，先确认程序计算位置与 CAD 中的实际位置一致。

### 4. 单图框实验

只针对一个人工确认的图框做实体归属，输出归属清单和未归属清单，暂不处理多图框竞争。

### 5. 多图框归属

在单图框结果稳定后，再加入相邻图框、边界对象和跨框块的明确状态机，不再通过大量特例补偿。

### 6. 保真导出

最后才加入块依赖保留、代理对象处理、DXF 导出和输出后重新读取审计。

### 7. 输出后审计和回归

对导出的 DXF 重新读取，检查实体句柄、边界、块依赖和文件结构；用固定样本建立回归集，防止修复一个坐标问题后引入新的归属问题。

## 目录结构

```text
main.py          命令行入口，支持文件选择和 audit 命令
audit.py         DXF 事实审计，不包含拆图补偿逻辑
file_picker.py   DXF 文件选择窗口
frame_detection.py 简单图框候选识别和可读报告
requirements.txt Python 依赖
原始文件/       输入样本，保留不改
.tools/          保留的外部工具目录，当前 DXF 流程不依赖
```

## 当前输出的意义

审计报告中的 `unbounded_entities` 只表示程序当前无法为对象建立可靠包围盒，并不表示这些实体没有几何位置。后续需要按实体类型分别处理，不能把所有无法计算的对象统一塞给某个图框。

同样，`model_space.extents` 只代表有效包围盒的整体范围，不代表图纸范围，也不能直接用于图框识别。

## 项目验收标准

新算法进入自动拆图阶段前，至少需要满足：

- 坐标空间和单位信息可追溯；
- 普通实体的模型坐标与 CAD 显示位置一致；
- 块的嵌套变换可解释；
- 无法定位的对象有明确原因；
- 单图框实验没有明显坐标偏移和归属遗漏；
- 所有输出实体都有来源句柄和归属状态；
- 输出文件可以重新读取并通过结构审计。
